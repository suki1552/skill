# OB 콜봇 데모 가이드 (시연 런북)

> 출동 최적화 스케줄링 Agent · 임원/고객 데모용 시연 대본과 활용 가이드
> 대상 시간: **약 10분** · 준비물: 노트북 + 브라우저(Chrome 권장)

---

## 0. 30초 요약 (엘리베이터 피치)

> "개통·장애 방문 일정의 **예약·안내·변경·취소를 콜봇이 자동으로 완결**합니다.
> PDS 자동 발신 + 런처 화면 팝업으로 통화 성공률을 높이고, Swing에 실시간 반영해
> **SM 추가 출동을 줄이고 고객 만족도를 높입니다.**"

핵심 메시지 3가지:
1. **자동화** — 사람이 하던 일정 조율을 콜봇이 대신
2. **크로스 채널** — 통화(음성) + 화면 팝업(시각)으로 완결
3. **연동** — Swing/PDS와 실시간 연동으로 운영에 바로 반영

---

## 1. 데모 준비 (시작 5분 전)

1. `ob-callbot/index.html`을 브라우저에서 엽니다. (더블클릭 → 설치 불필요)
2. **데이터 초기화** (깨끗한 상태로 시작하려면):
   - 브라우저 개발자도구(F12) → Console에 아래 입력 후 Enter, 새로고침
     ```js
     localStorage.clear()
     ```
   - 또는 각 화면의 초기화 버튼 사용 (콜봇 콘솔 "큐 초기화", Flow "메모 초기화")
3. 화면 4개를 각 탭으로 미리 열어두면 전환이 매끄럽습니다.
   - `index.html` / `landing.html` / `flow.html` / `simulator.html` / `dashboard.html`
4. **대시보드를 한 번 열어두기** (권장): 대시보드를 처음 열면 샘플 9건이 자동 생성됩니다.
   이렇게 해두면 STEP 5에서 콜봇으로 만든 건이 **기존 데이터 위에 얹혀** 화면이 풍성해집니다.
   (완전 백지 상태로 시작하고 싶으면 이 단계를 생략하세요.)

> 💡 **주의**: 데이터는 브라우저 localStorage에 저장됩니다. 시연은 **같은 브라우저**에서 진행해야 콜봇 콘솔 → 대시보드 연동이 보입니다.

## 2. 10분 시연 대본 (Step by Step)

각 단계의 **[화면] / [동작] / [멘트]** 를 그대로 따라 하면 됩니다.

### STEP 1 — 문제 제기 (1.5분) · `landing.html`
- **[동작]** 랜딩 페이지 상단부터 아래로 스크롤 (도입 배경 → 기존 문제 vs 솔루션)
- **[멘트]**
  > "지금은 방문 일정을 전화·문자로 일일이 조율합니다. 상담 리소스가 많이 들고,
  > 잦은 변경·취소로 기사 동선이 비효율적이며, 불필요한 SM 출동도 생깁니다.
  > OB 콜봇은 이 과정을 자동화합니다."
- **[포인트]** '기존 문제(빨강)' → 'OB 콜봇 솔루션(보라)' 대비 카드에서 잠깐 멈추기

### STEP 2 — 핵심 기능 & 효과 (1.5분) · `landing.html`
- **[동작]** 핵심 기능 3카드(PDS·런처·Swing) → 성과 밴드(78.6% / -34% / -21% / 24·7)
- **[멘트]**
  > "3가지 기술이 하나로 이어집니다. PDS가 대상 고객에게 자동 발신하고,
  > 런처가 통화와 동시에 화면에 팝업을 띄워 통화 성공률을 높이며,
  > 결과는 Swing에 실시간 반영됩니다. 그 결과 SM 추가 출동을 34% 줄일 수 있습니다."

### STEP 3 — 동작 흐름 이해 (1.5분) · `flow.html`
- **[동작]** Flow 편집기 열기 → '개통 방문일정 예약' 탭 → **'본인 확인' 노드 클릭**
- **[멘트]**
  > "콜봇 대화는 이 흐름을 따릅니다. 발신 → 런처 유무 분기 → 본인 확인 →
  > 일정 예약. 각 단계에 운영 규칙(메모)을 붙여 관리할 수 있고,
  > 미응답 시엔 재시도 후 문자로 자동 대체됩니다."
- **[포인트]** 노드 클릭 시 오른쪽 편집 패널에 메모를 적어 "운영 규칙까지 문서화된다"는 점 시연. 탭을 바꿔 **장애(CEI 진단 분기)** 흐름도 잠깐 보여주기

### STEP 4 — 콜봇 실제 실행 ⭐핵심 (2.5분) · `simulator.html`
- **[동작]**
  1. 콜봇 실행 콘솔 열기 → 왼쪽 **발신 대상 큐에서 '김민준(개통)' 선택**
  2. 콜봇이 자동 발신 → **"네, 가능합니다"** 클릭
  3. 본인 확인 → **"네, 맞습니다"** 클릭
  4. **런처 팝업 배너**가 뜨는 것을 가리키며 → 달력에서 **날짜 슬롯 하나 클릭**
  5. "예약이 확정되었습니다" + **"대시보드에 저장되었습니다"** 메시지 확인
- **[멘트]**
  > "고객 입장에서 보겠습니다. 콜봇이 전화를 걸면 동시에 화면에 이 팝업 배너가 뜹니다(런처).
  > 고객은 말로 답하거나 화면에서 바로 날짜를 고를 수 있습니다.
  > 예약이 끝나면 Swing에 반영되고 확인 문자가 자동 발송됩니다 —
  > 그리고 방금 이 건이 **운영 대시보드에 실시간으로 저장**됩니다."

### STEP 5 — 운영 화면 반영 확인 (1.5분) · `dashboard.html`
- **[동작]** 대시보드 열기 → **맨 위에 방금 예약한 '김민준' 건**이 있는 것을 확인
  - 상태를 드롭다운으로 **'방문 완료'로 변경** → 즉시 저장
  - 검색창에 이름 입력 → 필터 → **CSV 내보내기** 클릭
- **[멘트]**
  > "방금 콜봇으로 처리한 건이 운영 화면에 바로 들어왔습니다.
  > 관리자는 여기서 상태를 바꾸거나 기사 배정을 수정하고,
  > KPI와 처리 결과 분포를 실시간으로 봅니다. 데이터는 CSV로 내보내
  > 기존 리포트에 붙일 수 있습니다."

### STEP 6 — 마무리 & 리드 수집 (30초) · `landing.html`
- **[동작]** 랜딩 하단 → **"도입 상담 신청"** 버튼 클릭 → 폼 시연
- **[멘트]**
  > "도입을 검토하시면 이 폼으로 상담을 신청할 수 있습니다.
  > 오늘 보신 것처럼, 발신부터 운영 반영까지 한 번의 통화로 완결됩니다."

## 3. 화면별 상세 사용법

### 🚀 랜딩 (`landing.html`)
- 상단 네비게이션(배경/핵심기능/서비스영역/동작흐름)으로 섹션 이동
- **도입 상담 신청** 버튼 → 폼 작성 → 접수번호 발급 (localStorage 저장)

### 📞 콜봇 실행 콘솔 (`simulator.html`)
- **발신 대상 큐**: 고객 클릭 시 해당 시나리오로 콜봇 발신 시작
- **+ 대상 추가**: 고객명·연락처·영역·시나리오 입력해 큐에 등록
- **큐 초기화**: 샘플 대상으로 리셋
- 시나리오 3종: 개통 방문예약 / 개통 D-1 / 장애 D-1(CEI 진단 분기)
- 처리 완료 시 → 대시보드에 자동 저장 + 큐에서 제거

### 📊 관리 대시보드 (`dashboard.html`)
- 콜봇 처리 결과 실시간 반영 (없으면 샘플 9건 자동 표시)
- **상태 변경**(드롭다운) · **기사 배정**(입력) · **삭제** · **+ 일정 추가**
- **검색**(고객명/기사/연락처) · **영역 필터**(개통/장애) · **CSV 내보내기**
- 상단 KPI·막대차트·도넛은 데이터 기준 자동 계산

### 🔀 Flow 편집기 (`flow.html`)
- 탭으로 3개 흐름 전환
- 노드 클릭 → 경로 강조 + 오른쪽 패널에서 **라벨·업무 메모 편집·저장**
- 메모가 있는 노드엔 ✎ 배지 표시
- **SVG 내보내기**로 다이어그램을 문서/PPT에 첨부
- **메모 초기화**로 현재 흐름 편집 리셋

## 4. 예상 Q&A 대응

| 질문 | 답변 포인트 |
|------|-------------|
| "실제 시스템과 어떻게 연동되나요?" | 콜봇 결과는 Swing에 실시간 반영, PDS로 자동 발신. 오늘 데모의 localStorage 저장이 실제로는 Swing/PDS API 연동으로 대체됩니다. |
| "고객이 전화를 안 받으면요?" | 미응답 시 재시도 후 **문자 발송으로 자동 대체**됩니다. (Flow에서 점선 경로로 확인) |
| "장애 건은 무조건 방문하나요?" | 아니요. **CEI 원격 진단**으로 정상 복구가 확인되면 방문 없이 자동 취소 처리해 불필요 출동을 줄입니다. |
| "런처가 없는 고객은요?" | 런처 미설치 고객은 문자 발송 채널로 분기 처리됩니다. (Flow의 '런처 無' 경로) |
| "효과 지표는 실제인가요?" | 데모 수치는 예시입니다. 실제 도입 시 PoC를 통해 자동처리율·출동 감소율을 측정·검증합니다. |

## 5. 트러블슈팅

- **대시보드에 콜봇 처리 건이 안 보임** → 같은 브라우저에서 열었는지 확인. 다른 탭이면 새로고침(F5)
- **데이터가 꼬였을 때** → F12 콘솔에서 `localStorage.clear()` 후 새로고침
- **폰트/이모지가 다르게 보임** → Chrome 최신 버전 권장
- **처음처럼 되돌리기** → 콜봇 콘솔 "큐 초기화" + 대시보드에서 항목 삭제 또는 `localStorage.clear()`
